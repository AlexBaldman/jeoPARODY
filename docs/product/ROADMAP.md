# Product Roadmap

This is the **current priority map**, not an eternal feature wishlist. `DEV_JOURNAL.md` owns the freshest handoff; this file owns the durable cascade.

## North star

Build a funny, genuinely educational trivia product whose presentation system becomes progressively more expressive without sacrificing deterministic gameplay, accessibility, or maintainability.

## Current cascade

```text
GREEN CANONICAL RUNTIME
        ↓
ERGONOMIC KNOWLEDGE / AGENT SYSTEM
        ↓
PROVE FOOTER STAGE + HOST ACTOR
        ↓
RETIRE DUPLICATE HOST-ANIMATION OWNERS
        ↓
EXPAND RESPONSIVE / FULLSCREEN STAGE
        ↓
ADD NAMED CHOREOGRAPHY + PERFORMANCE TIMELINE
        ↓
MINE JEOPARDISH DONOR BEHAVIOR IN VERTICAL SLICES
        ↓
NORMALIZE REMAINING STATE / EVENT / CSS OWNERSHIP
```

## Now

### Documentation and collaboration
- one canonical agent entrypoint (`AGENTS.md`);
- one documentation map (`docs/README.md`);
- current architecture/product/reference docs separated from archive;
- stale tool-specific instructions reduced to compatibility pointers;
- historical plans preserved without masquerading as current truth.

### Stage / mobile
- keep protected desktop and iPhone runtime checks green;
- refine footer Stage rail and host scale across short/tall/landscape viewports;
- add explicit host-position/choreography assertions where useful;
- progress toward installed/fullscreen/PWA presentation while respecting safe areas.

### Host performance
- consolidate old animation-manager paths behind `HostStageActor`/`HostSystem` ownership;
- turn funny host hijinks into named reusable choreography beats;
- pressure-test a small timed performance-cue format;
- begin layered/rigged-host experiments only when they improve real performances;
- connect transcript/voice timing to a minimal viseme mouth system.

## Next

### Donor mining
Use Jeopardish and historical jeoPARODY branches as quarries. Prefer high-value proven behavior:

- scoring/judgment fixtures;
- episode/round contracts;
- Study/learning behaviors;
- HostPack/avatar/performance semantics;
- media/localization/accessibility contracts.

Every port begins from current `main`, has one owner, and keeps the production spine green.

### Asset intelligence
Continue evolving the asset lifecycle:

```text
immutable source
→ provenance/hash
→ transcription/analysis
→ semantic metadata
→ searchable catalog
→ rights/eligibility gate
→ runtime projection
```

The Trebek audio archive is the first rich specimen. The same pattern should eventually support images, sprites, video, animations, props, and generated assets.

## Maintenance stream

Apply the Bus-the-Table Rule continuously. Maintain a separate explicit queue for work that is too large or risky for opportunistic cleanup, including:

- dependency/security audit and Node/toolchain upgrades;
- shrinking legacy CSS override layers;
- stale compatibility-bridge removal;
- branch retirement after asset preservation;
- warning/dead-code cleanup;
- documentation link/integrity checks.

## Definition of progress

Prefer changes that reduce ambiguity, remove duplicate ownership, strengthen deterministic evidence, or create a reusable primitive proven by real use. Feature count alone is not progress.
